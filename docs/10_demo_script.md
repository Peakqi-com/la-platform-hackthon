# 10 Demo 腳本（決賽現場／影片用，約 8 分鐘）

主軸一句話：**估價單位送來什麼，系統就依查估辦法與作業手冊逐格核算；沒送書表時，只給地號也能先產出一版。** 每個數字都能點回法源，推定值只標「需確認」不判錯。

## 0. 事前準備（開場前 10 分鐘）

| 項目 | 做法 |
|---|---|
| 清空案件 | `data/cases/*.json` 與 `data/audit/<案件>.jsonl` 移到備份資料夾，重啟後端（案件清單在記憶體，不重啟不會消失） |
| 啟動 | 後端 `cd backend && python3 -m uvicorn app.main:app --port 8000`；前端 `cd frontend && npm run build && BACKEND_URL=http://127.0.0.1:8000 npx next start -p 3000` |
| 暖機 | 開一次 `http://localhost:3000/`，等首頁「底圖快取／設施資料庫」數字出現；後端啟動會在背景預載金山區路網（約 30 秒） |
| 瀏覽器 | Chrome 視窗 1440×900、縮放 100%、關閉書籤列；左下角「操作身分」先填好姓名與角色（承辦） |
| 檔案 | `docs/reference/查估書表範本.pdf` 放桌面（上傳用） |
| 備援 | 若外網不通：金山、萬里、石門、三芝底圖已離線快取，其他區地圖會空白；實價登錄、指數、分區、設施全在本機，不受影響 |

時間分配：場景 1 三分鐘、場景 2 兩分鐘、場景 3 兩分鐘、收尾一分鐘。

## 1. 場景一：估價單位送來六頁書表 → 三分鐘內完成逐格核算（3 分）

**口白**：這是估價單位依作業手冊送來的六頁查估書表 PDF。承辦以前要拿著基準明細表一格一格對，現在把 PDF 丟進來。

| 步驟 | 操作 | 觀眾看到 | 截圖 |
|---|---|---|---|
| 1-1 | 首頁「案件總覽」，指一下四步驟卡片 | 輸入 → 產出 → 審查 → 輸出，案件數 0 | `01_home.png` |
| 1-2 | 把 `查估書表範本.pdf` 拖進「審查送審書表」 | 辨識結果：六頁各自辨識到哪一表、案號 1140901-99-001、比準地金美段489、缺漏 0、低信心 0 | `02_import_preview.png` |
| 1-3 | 按「建立案件並開始審查」 | 直接跳到「③ 審查」：全部相符、1 項需確認；系統核算比較價格 212,958 元/m²、比準地地價 213,000 | `03_review_pass.png` |
| 1-4 | 指「需確認」那一列：道路種類最大修正率 8% 超過內政部基準表上限 5% | 說明欄寫明「需確認（不判錯）」，依據欄「手冊 p.52–53、附件 25」 | `04_review_confirm_row.png` |
| 1-5 | 按該列「看基準表格位」 | 彈出評價基準明細表的判定條件與矩陣格位 | `05_rule_cell.png` |
| 1-6 | 上方「② 產出書表」 | 六頁書表照範本版面重排，第 1 頁勘查表、第 3 頁比較法估價表 | `06_sheets.png` |
| 1-7 | 「地圖（互動檢視）」 | 區段範圍、比準地、設施距離線；右側「比準地接近條件與嫌惡設施」每筆標來源（送審書表抽取／步行距離） | `07_map.png` |

**講重點**：
- 數字全由規則引擎依查估辦法 §13、§17、§18、§19 與手冊頁碼計算，沒有語言模型參與算數。
- 「需確認」與「不符」分開：推定或範本本身的疑點不判錯，讓承辦決定。

## 2. 場景二：填載有錯的送審書表 → 不符項、承辦裁決、意見書（2 分）

**口白**：同一案，如果估價單位抄錯了等級或修正率會怎樣。

| 步驟 | 操作 | 觀眾看到 | 截圖 |
|---|---|---|---|
| 2-1 | 回「案件總覽」→「其他範例」→「範例二：含填載錯誤之送審書表」 | 進「② 產出書表」後按「審查 →」 | — |
| 2-2 | 「③ 審查」 | 5 項不符、1 項需確認；每列有「估價單位填載／系統核算／說明／依據」 | `08_review_mismatch.png` |
| 2-3 | 篩選「只看比較標的1」，指一列：例如個別因素等級填 2 但依基準表應為 3，修正率連動 | 「依據」寫手冊頁碼與基準表格位 | `09_mismatch_row.png` |
| 2-4 | 對一列選「接受填載」填說明「經審酌採估價單位現勘結果」，其餘「維持不符」，按「儲存裁決」 | 裁決寫進操作紀錄 | `10_decision.png` |
| 2-5 | 「下一步：審查意見書」 | 意見書：結論「不符，請補正」、核算摘要、逐條意見含法源與承辦裁決、落款 | `11_opinion.png` |
| 2-6 | 「④ 輸出」 | 一列多格式：書表 Excel／PDF、意見書 Word／PDF、三張圖 PNG、下載全部 zip | `12_export.png` |

**講重點**：不符項不是系統說了算，承辦「接受填載」或「維持不符」都寫進意見書與操作紀錄，可追溯。

## 3. 場景三：沒有書表，只有年期與地號 → 一鍵產出一版書表（2 分）

**口白**：徵收案剛開始時往往只有地號。系統用地籍圖、都市計畫圖、路網、設施庫、實價登錄先產出一版，讓估價師從「改」開始而不是從「填」開始。

| 步驟 | 操作 | 觀眾看到 | 截圖 |
|---|---|---|---|
| 3-1 | 「案件總覽」→「一鍵建案」：案號 `1140901-99-002`、基準日 `1140901`、金山區、比準地 `金美段489地號`、商業用地，勾「建立後立即依地號產生書表」，按「建立並產生」 | 約 30 秒，進「① 輸入資料」的「填寫結果清單」 | `13_onekey_form.png` |
| 3-2 | 指清單上方四類統計：資料／量測／推定／空白 | 地籍界線→宗地屬性→區段範圍（路網推估街廓）→勘查表 28 欄→設施距離→實價登錄比較標的 3 件 | `14_fill_report.png` |
| 3-3 | 指比較標的：實價登錄自動選取，依 §19 第 2 項標選取依據；含建物者已依第四號公報推定建物成本價格；期日調整用都市地價指數內插 | 每一筆都有來源與法源 | `15_comparables.png` |
| 3-4 | 「② 產出書表」→ 第 1 頁勘查表 | 建蔽率／容積率來自金山細部計畫土管要點第四點；淹水潛勢、地勢、店舖毗連都標「推定」 | `16_generated_sheet.png` |
| 3-5 | 「③ 審查」 | 推定值只列「需確認」，不列不符 | — |

**講重點**：推定規則全部寫在 docs/07（門檻是系統自訂，寫出來讓人能質疑）；資料來源標示在頁腳（國土測繪中心、OSM、政府開放資料）。

## 4. 收尾（1 分）

- 三種入口一張圖：送審書表 PDF／範例／地號。
- 產出：六頁書表（Excel、PDF）、審查意見書（Word、PDF）、三張圖說、操作紀錄。
- 沒做的事說清楚：收益法（查估辦法 §14）、樓層別效用比率、地籍圖 API（現用匯入圖檔或預載）、語言模型潤飾預設關閉。

## 5. 常見提問與回答

| 問 | 答 |
|---|---|
| 數字會不會是 AI 亂算？ | 不會。算式全在規則引擎，每條對回查估辦法條號與手冊頁碼（docs/07）；語言模型只用於意見書潤飾且預設關閉、有守門檢查。 |
| 推定值錯了怎麼辦？ | 推定值一律標「推定／需確認」，只提醒不判錯；估價師填的值優先。 |
| 建蔽率容積率哪裡來？ | 施行細則附表一＋各計畫區土管要點自動抽取（48 個計畫區），多表不一致標需人工核對。 |
| 實價登錄含建物怎麼扣？ | 第四號公報成本法（每坪營造施工費 × 坪數 × 定額折舊 × 營造工程物價指數），標推定需確認。 |
| 換別的區可以嗎？ | 全新北市路網、設施、分區、門牌都在本機；地籍圖需匯入圖檔或申請國土測繪中心 API。 |
| 部署？ | 單機即可（FastAPI＋Next.js，無 docker），見 deploy/runbook_ec2.md。 |
