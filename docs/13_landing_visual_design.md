## 實際上線的首頁（城市起風）

| 項目 | 位置 |
|---|---|
| 原始碼（不要直接改） | `city-wind-source/city-wind/dist/`，維持原樣 |
| 實際服務的副本 | `frontend/public/city-wind/` |
| 路由 | `next.config.ts` 的 `rewrites.beforeFiles`：`/` → `/city-wind/index.html` |
| 舊介紹頁 | `frontend/app/page.tsx` 留著當退路，rewrite 失效時 `/` 不會 404 |

**更新原始碼的流程**（原始碼換新版時照做）：

1. 保留 `enter.css`，其餘清掉，再把 `city-wind-source/city-wind/dist/` 整個複製過去（含 `systems/` 子目錄）。
2. 重套下列三處整合（`index.html` 目前在改版間維持不變，可原樣重套）。
3. **一定要重新 `npm run build`。** Next 的 `public/` 檔案清單在 build 時決定，
   build 之後才新增的檔案或目錄會 404。`systems/` 就是這樣踩到的。

整合時在副本上做了三件事，原始碼那份沒動：

1. **資源路徑改絕對路徑。** 原本是 `./style.css`、`./app.js`，在 `/` 底下會解析成 `/style.css` 而 404，
   改成 `/city-wind/…`。`app.js` 內部的 `./city.js`、`./three.module.min.js` 是相對模組網址解析，不必改。
2. **加入系統入口** `frontend/public/city-wind/enter.css`（只加不改，沿用原站的 `--accent` / `--line`）：
   頁首「進入系統 →」與結尾「進入案件總覽 →」，都指向 `/dashboard`。
3. **結尾兩個出口並成一列**（`.ending-actions`）。分開直排會把原本的「重新走進城市」擠到頁尾 HUD 上，
   在 1280×720 重疊約 50 px。

### 在原始碼之上做的畫質與操作修正（2026-09-13）

這四項改在 `frontend/public/city-wind/`，原始碼那份沒有。換新版原始碼後要重做。

| 檔案 | 改了什麼 | 為什麼 |
|---|---|---|
| `app.js` | 錨點捲動落在區段 **34%** 而非頂端（`CHAPTER_ANCHOR`），`location.hash` 還原同樣處理 | 章節文字的 fadeIn 要到 local `.18` 才滿，捲到區段頂端只有 **3% 透明度**，看起來像卡住不動。點導覽、點頁首、用網址帶 hash 都會踩到 |
| `systems/quality.js` | `dpr` 上限之外加 `ssaa` 下限；`pixelRatio` 改 `max(native, …)`；分級條件 `cores>=8 \|\| memory>=8`；降級下限放寬到 `.5`（有 native 保底） | 舊式 `min(devicePixelRatio, dpr)` 在 devicePixelRatio=1 的一般螢幕永遠等於 1，再乘 `resolutionScale` 就低於原生解析度。實測有效 dpr 只有 **0.90**，所以糊。改後 **1.50**，且效能不足時最多退回原生，不會更糊 |
| `systems/quality.js` | 新增 `?q=LOW\|MEDIUM\|HIGH` 覆寫自動分級 | 現場筆電效能未知。卡就 `?q=LOW`，機器夠力就 `?q=HIGH` |
| `systems/materials.js` | 牆體法線改用 `facadeNormal()`（樓板線＋板縫）取代借用的柏油雜訊；環境貼圖 128×64 → 256×128，分天頂／地平／地面反照三段加太陽亮斑與雲帶 | 建築原本是素色塊面沒有樓層尺度；環境貼圖太單純，玻璃與車體反射沒有層次 |

**材質改動的分寸**：第一版一次把 `map`＋`roughnessMap`＋`normalMap` 三張貼圖加到 12 個材質，
著色器取樣數暴增，直接把測試用的軟體渲染分頁打掛。改成只替換既有的 `normalMap`（取樣數不變），
再加上環境貼圖是啟動時算一次，才在不增加每幀成本的前提下拿到細節。要再加材質細節前先確認這點。

為什麼走靜態直出而不是併進 App Router：那份 `style.css` 大量使用裸標籤選擇器（`header`、`nav a`、`h1`、`button`），
與 `globals.css` 的 Tailwind preflight 和 `html{font-size:20px}` 會互相覆蓋。靜態直出的行為與原始碼完全一致，
風險最低。部署不受影響：EC2 runbook 用 `npx next start`、Dockerfile 有 `COPY public`，兩條路徑都會服務 `public/`。

目前版本（2026-09-13 03:21 的原始碼）多了 `systems/`（life／lighting／materials／parcel／postprocessing／quality／state 七個模組），
`city.js` 由 11 KB 增為 24 KB，場景改為彩色並帶日夜循環（清晨→日間→午後→黃昏→夜晚）。

已驗證（1440×900、1280×720 與 390×844）：五個章節切換、導覽高亮、WebGL 場景、12 個 js 全部載入、
無失敗資源、無 console 錯誤、頁首與結尾兩個入口都進得到 `/dashboard`、結尾出口未壓到頁尾 HUD、手機版頁首不重疊也不橫向捲動。

## 六組標準色

五組沿用 Tailwind 內建色階——系統現有的按鈕、徽章、表格邊框用的就是這些值，換色等於重寫整包。
設計工作在於每組只准做一件事。第六組「炭」是自訂暖中性，從現有 `#FBF7F2`／`#2A1D14`／`#E2D6CC` 補成完整階。

| 組 | 核心值 | 職責 | 唯一規則 | 深底／淺底 |
|---|---|---|---|---|
| 土橙 Terra | `#EA580C` | 行動、承辦身分、比準地 | 只給按得下去的東西 | 400／600·700 |
| 測青 Survey | `#06B6D4` | 量測與空間、規則引擎算出的值 | 只給量到的與算出來的，永不做按鈕 | 400／700 |
| 核綠 Verified | `#059669` | 相符、已完成、可匯出 | 只給通過的結論 | 400／600·700 |
| 注意琥珀 Caution | `#F59E0B` | 需人工確認、需人工填載、產出已過期 | 只做狀態標示，絕不做按鈕 | 300／700 配 100 底 |
| 不符緋 Discrepancy | `#DC2626` | 填載值與核算值不同 | 一屏最多亮五格 | 400／600·700 |
| 炭 Carbon | 自訂 | 底色、文字、格線、卡片邊 | 取代表單控制項的冷灰 | 950／25 |

琥珀與土橙的分界是整套色最關鍵的一條：**橙＝要按，琥珀＝要看**。破了就分不清行動與狀態。

首頁走深底（炭 950），系統內頁維持紙底（炭 25）。最後一段底色過渡到紙色，按下 CTA 不會有跳窗感。

  --color-carbon-25:  #FBF7F2;   --color-carbon-600: #5C4B3D;
  --color-carbon-100: #EAE1D6;   --color-carbon-700: #43352A;
  --color-carbon-200: #E2D6CC;   --color-carbon-800: #2A1D14;
  --color-carbon-400: #A08D7C;   --color-carbon-950: #0E0906;
}
/* 首頁專用深底世界；系統內頁沿用既有 :root 不動 */
.landing {
  --ground: #0E0906;  --ink: #F3EAE0;  --line: #33241A;
  --terra: #FB923C;   --cyan: #22D3EE;

## 動起來的規矩

- **一個物件，六個狀態。** 整頁只有一個主體在變形：三維區段 → 攤平的鏈 → 對照表 → 數字 → 書表。不是六段各做各的特效。
- **捲動驅動，不自動播放。** 現場講解會停頓，自動播放的東西會講到一半跑掉。
- **靜止也要看得懂。** 關掉 JS、`prefers-reduced-motion`、投影機掉幀，訊息都不能少。
- **效能預算。** 首屏 1.5 秒內可讀；three.js draw call < 60、三角形 < 30k；捲動只改 `transform` 與 `opacity`。
- **字級不縮。** 首頁基準可用 16–18 px 換版面呼吸，但委員要讀的數字與標籤不得小於 16 px。

| 階段 | 時間 | 內容 | 狀態 |

## 技術決定

| 項目 | 決定 | 理由 |
|---|---|---|
| three.js / d3 | 走 npm 進 bundle | 不依賴外部 API 是專案原則；CDN 斷了首頁就毀了 |
| 字型 | 自架 woff2 放 `public/` | 同上，中文字型尤其大 |
| 3D 資料 | 只用 `fixtures/` 已進 git 的幾何 | 首頁不依賴 `data/`，重建失敗也不影響開場 |
| 體積 | three.js 動態 import，首屏不含 | 首屏可讀優先於 hero 早零點幾秒出現 |
| 深淺主題 | 首頁固定深底，系統固定紙底，不做切換 | 多一個狀態就多一組要測的畫面 |
| 動畫庫 | 不裝，用 `IntersectionObserver` + CSS | 需求只有捲動進度與 transform |

## 不做的事

- 不做粒子、星空、漸層光暈。有真的地籍界線與真的距離，用假的裝飾反而扣分。
- 不做數字跑馬。212,958 是驗收過的值，安靜待著比滾上去有說服力。
- 不碰系統內頁。內頁的冷灰改色列為賽後項目。
- 不放團隊介紹與比賽字樣（沿用「介面文字不出現主辦、比賽等字樣」的既有約定）。

## 驗收條件

拔掉網路線、1440×900 Chrome、縮放 100%，從首頁捲到底再按進案件總覽，
全程不掉幀、沒有空圖、沒有英文佔位字。過了才算完成。
