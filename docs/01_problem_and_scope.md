# 01 題目、範圍與 Demo 腳本

## 題目（地政局命題原文重點）

估價案件審查時，審查人員要人工比對地價區段勘查表（表1）、影響地價區域因素分析明細表（表5）、
比較法調查估價表（表4），逐項核對優劣等級、修正率、加總與跨表抄填，耗時且易錯；
各案的基準明細表還可能因個案調整。預期成果：

1. 透過 AI 輔助完成估價書**填寫**流程
2. 降低人工審查時間與錯誤率，提升一致性
3. 作為估價審查數位化的基礎案例

提供資料：查估書表範本（金山區 P002-00 一個案例、一個比較標的）、作業手冊、金山區商業用地基準明細表。
「不限以上資料，可自行從公開網站蒐集」。

## 四份文件的關係

題目 → 規則（手冊）→ 參數（基準明細表）→ 實例（書表範本）。
手冊 p.11–13 已經寫了審查重點清單（iii/vi/vii/x），題目痛點與它一一對應；
基準明細表是各縣市自訂的具體判定條件與修正率矩陣；範本是套用結果。
系統本質是**規則引擎 + 跨表一致性驗證**，不是 ML 預測。

## 當天情境的三種深度

| 深度 | 主辦給什麼 | 我們要做什麼 |
|---|---|---|
| 淺 | 填好的表1 + 宗地清冊(表7) + 實例 + 基準表 | 等級判定、查矩陣、加總、抄填 |
| 中 | 地籍、實例、基準表；表1 空白 | 從 POI/分區/路網反推勘查表事實，再做淺 |
| 深 | 連地價區段都沒劃、三張圖也空白 | 先劃區段（以公告現值區段 bootstrap）、畫圖，再做中 |

**目標：深。備選：中。保底：淺。** 管線每一格都要能「自動推算」也能「人工填入」，當天資料不夠就在 UI 上手動補。
**2026-09-07 確認：勘查表（表1）視為產出。** 當天很可能只拿到年期、區段編號、區段範圍，其餘欄位由系統推算（`survey_draft`），推不出的標需人工填載。

## MVP 必要功能

- ✅ 基準表 JSON 化 + 規則引擎（等級/矩陣/加總/價格鏈）— 沒有這個就不是這個產品
- ✅ 審查模式：估價師表 vs 引擎表 → findings（引用手冊條號與基準表格位）
- ✅ 填寫模式：事實 → 表5、表4（Excel 輸出，照範本格式）
- ✅ 距離模組：直線/步行、參照設施、來源標註
- ✅ 三張圖（區段略圖、分區圖、區段圖）— 至少 Leaflet 疊圖加標註
- ✅ 委員可操作的網址：預載案例、上傳、防呆
- ❌ 收益法、成本法（範本沒用到，時間不夠不做）
- ❌ 多縣市基準表自動抓取（做成可替換即可）
- ❌ 使用者帳號、權限

## Demo 腳本（先寫腳本再倒推功能）

1. **信任基礎**：載入地政局範本 → 全綠，引擎完整重現 13.00% / 212,958。
2. **抓錯**：載入我們竄改過的版本（面前道路 6m→12m、某小計加錯、區域因素抄錯到表4）→ 逐條 findings，每條標依據。
3. **填寫模式**：輸入一組新的勘查事實（或當天的新標的）→ 自動產表5、表4，含距離來源與量測方式。
4. **換基準表**：換一份住宅用地/另一區的基準表 JSON → 規則跟著換，證明沒寫死。
5. **地圖**：點宗地，顯示到各設施的直線/步行距離線、等級、基準表格位高亮。

呈現三件都準備：簡報（架構 + 規則對應）、live demo（網址）、影片（網路掛掉的保險，賽前錄）。
